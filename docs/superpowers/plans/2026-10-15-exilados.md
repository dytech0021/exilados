# Exilados: plano de execução

> Execução nativa, tarefa a tarefa, pelo próprio assistente (o dono pediu para fazer tudo sem novas perguntas).

**Objetivo:** pôr no ar o Exilados descrito na especificação: banco, exilados-api, LiveKit, site com texto, voz e
lives, o programa do Windows, e tirar lives e amigos do Ponte.

**Arquitetura:** Supabase do FilaBox (tabelas `exilados_*`, regras de acesso, tempo real, imagens); servidor atual
com exilados-api (Node 24, sem pacotes), LiveKit (voz) e MediaMTX (lives); site estático em
`https://filabox3d.com.br/exilados/`; programa C# / .NET 10 para transmitir.

**Ferramentas:** Node 24 (`node --test`), PostgreSQL do Supabase, LiveKit 1.13.7, `lk` 2.18.7 para testes de voz,
supabase-js 2.117.2 e livekit-client 2.22.3 copiados para `site/vendor/`, .NET 10.

**Especificação:** `docs/superpowers/specs/2026-10-15-exilados-design.md`.

## Restrições globais

- Repositório público: nenhuma chave, senha, token ou e-mail pessoal entra nele.
- Endereço: `https://filabox3d.com.br/exilados/`; API em `/exilados/api/`; voz em `wss://filabox3d.com.br/exilados`
  (o cliente do LiveKit acrescenta `/rtc`); lives em `/exilados/ao-vivo/`; atualização em `/exilados/atualizacao/`.
- Supabase `kobtvgqnitdeviddvymm`; só objetos com prefixo `exilados_` (e a pasta `exilados` do armazenamento).
  Nada do FilaBox muda.
- Portas no servidor: exilados-api 7415 (pública pelo nginx) e 7416 (autorização do MediaMTX, só 127.0.0.1);
  LiveKit 7880 (só 127.0.0.1), TCP 7881 e UDP 7882 (públicas). O relay do Ponte continua em 7414.
- Até 30 membros; até 20 por sala de voz; mensagens de até 2.000 caracteres; imagens de até 600 KB depois de
  reduzidas (lado maior 1.600; perfil 256 × 256).
- Textos da interface em português do Brasil; aparência do Discord (cores da seção 5.2 da especificação).

## Pontos de atenção (não cobertos por um teste de tarefa óbvio)

1. Membro removido com o site aberto: a próxima ação dele falha com "Você não faz mais parte do grupo" e a voz cai.
   Teste: `rotas.test.mjs` (voz negada a inativo) e `testes.sql` (leitura negada a inativo).
2. Convite usado por quem já é membro: não duplica nem rebaixa o dono. Teste: `testes.sql`.
3. Live do MediaMTX com caminho do Ponte (`ao/...`): continua sendo decidida pelo relay. Teste: `mediamtx.test.mjs`.
4. Mensagem só com imagem, ou só com texto, as duas válidas; vazia recusada. Teste: `testes.sql`.
5. Token do Supabase vencido no meio da sessão: o site renova sozinho antes de chamar a API. Teste: `api.test.mjs`
   do site (renovação antes da chamada).

## Etapa 1: servidor e contas

### Tarefa 1: repositório
- Criar `README.md`, `.gitignore` (`.superpowers/`, `node_modules/`, `*.env`, `windows/bin`, `windows/obj`).
- `gh repo create dytech0021/exilados --public --source . --push`.

### Tarefa 2: banco
- **Arquivos:** `banco/001_exilados.sql` (tabelas, índices, funções, regras, pasta de imagens, tempo real),
  `banco/testes.sql` (bloco que cria usuários simulados, confere as regras e desfaz tudo no fim).
- **Funções (interface para o site e a API):**
  - `exilados_e_membro() returns boolean`, `exilados_e_dono() returns boolean`,
    `exilados_sao_amigos(x uuid, y uuid) returns boolean` (todas `security definer`, `stable`).
  - `exilados_criar_convite() returns text` (código de 64 caracteres; guarda o SHA-256; 7 dias).
  - `exilados_info_convite(codigo text) returns table(valido boolean, convidado_por text)`.
  - `exilados_entrar(codigo text, nome text) returns void`.
  - `exilados_definir_ativo(alvo uuid, ativo boolean) returns void` (só o dono; nunca o próprio dono).
  - `exilados_abrir_conversa(outro uuid) returns uuid` (só entre amigos; cria ou devolve).
- **Aplicação:** pelo editor de SQL do painel do Supabase; depois `testes.sql`, que termina com
  `RESULTADO: tudo certo` (ou a primeira falha). Dono e salas iniciais por um comando avulso, fora do repositório.

### Tarefa 3: exilados-api
- **Arquivos:** `api/package.json`, `api/src/{config,jwt,supabase,livekit,lives,mediamtx,rotas,servidor}.mjs`,
  `api/test/{jwt,lives,mediamtx,rotas}.test.mjs`.
- **Interfaces:**
  - `assinarJwt(payload, segredo) -> string` (HS256).
  - `tokenDoLiveKit({chave, segredo, identidade, nome, sala, segundos}) -> string`.
  - `new Supabase({url, chave, fetch})`: `usuario(token)`, `membro(token, id)`, `sala(token, id)`,
    `rpc(token, nome, args)`, `gravarLive(token, id, caminho)`, `sinalLive(token, id)`, `apagarLive(token, id)`.
  - `new LiveKit({api, chave, segredo, fetch})`: `listarSalas()`, `removerParticipante(sala, identidade)`,
    `tirarDeTodas(identidade)`.
  - `new Lives({segredo, agora})`: `comecar(id) -> {caminho, senha}`, `sinal(id) -> boolean`, `parar(id)`,
    `donoDe(caminho) -> id|null`, `podeEnviar(caminho, usuario, senha)`, `leitura(caminho) -> token`,
    `podeLer(caminho, token)`.
  - `autorizar(pedido, {lives, repassar}) -> Promise<boolean>`; `contarLeitores(caminho) -> Promise<number>`.
- **Rotas** (todas com `Authorization: Bearer <token do Supabase>` e membro ativo): `GET /saude` (sem login),
  `POST /voz/entrar {sala}`, `POST /membros/ativo {usuario, ativo}`, `POST /live/comecar`, `POST /live/sinal`,
  `POST /live/parar`, `POST /live/assistir {usuario}`.
- **Testes:** `cd api && node --test` com Supabase, LiveKit, MediaMTX e relay falsos (servidores HTTP locais).

### Tarefa 4: servidor
- **Arquivos:** `servidor/livekit.yaml.exemplo`, `servidor/livekit.service`, `servidor/exilados-api.service`,
  `servidor/api.env.exemplo`, `servidor/nginx-exilados.conf`, `servidor/instalar.sh`, `servidor/publicar.ps1`.
- LiveKit em `/opt/livekit/1.13.7`, configuração em `/etc/exilados/livekit.yaml` (0600, entregue ao serviço por
  `LoadCredential`); exilados-api em `/opt/exilados/api`; site em `/var/www/exilados/www/exilados/`.
- nginx: um `include /etc/nginx/snippets/exilados.conf;` dentro do bloco do FilaBox, com `nginx -t` antes do
  recarregar e volta ao backup se falhar.
- MediaMTX: caminho `~^ex/[A-Za-z0-9]{24}$` e autorização em `127.0.0.1:7416` (a API repassa o resto ao relay).
- **Verificação:** `curl /exilados/api/saude`; `lk room join` com um token de teste publicando áudio de demonstração
  (mídia por UDP 7882 ou TCP 7881); autorização do MediaMTX para `ao/...` ainda decidida pelo relay.
